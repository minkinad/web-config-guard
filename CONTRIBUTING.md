# Участие в разработке

Создайте issue с воспроизводимым случаем перед крупным изменением. В PR опишите причину, поведение до и после, тесты и ограничения. Заголовок PR — Conventional Commit (`feat:`, `fix:`, `docs:` и т. д.); описание должно содержать не менее 20 символов. Автоматический release создаётся только по version tag `v*`, production deployment отсутствует.

Перед PR запустите `make setup`, `make check`, `make build`. Для Docker изменений — `make docker-build`; для стиля — `make fmt` и `make lint`. Не добавляйте внешние сервисы без потребителя. Обновляйте README/архитектуру/roadmap при изменении публичного поведения. Секреты и реальные ключи в репозиторий не помещайте.
